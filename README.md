# Граф зависимостей пакетов Ubuntu

Консольная программа строит граф зависимостей заданной версии пакета
Ubuntu и сохраняет его в SVG. Настройки читаются из JSON. Метаданные
Packages разбираются самостоятельно, без вызова apt из приложения.

## Запуск

Нужны Python 3.10 или новее и [D2](https://d2lang.com/tour/install/)
в переменной PATH. Проверка установки D2: `d2 --version`.
Сборка и установка Python-библиотек для запуска не требуются.

Linux и macOS:

```sh
sh run.sh --config examples/demo.json
```

Если установлен Make:

```sh
make run CONFIG=examples/demo.json
```

Windows (cmd):

```bat
run.bat --config examples/demo.json
```

Windows (PowerShell):

```powershell
.\run.bat --config examples/demo.json
```

Результат примера — `output/demo.svg`. Рядом сохраняется исходный
`output/demo.d2`. Стрелка направлена от пакета к его зависимости.

При необходимости D2 можно установить из проверенного официального архива:

```powershell
py -3 tools/install_d2.py .cache/d2
$env:PATH = "$PWD\.cache\d2;$env:PATH"
.\run.bat --config examples/demo.json
```

Если команда `python` печатает только `Python` и не выполняет скрипт,
проверьте `py -3 --version`. Нужна версия 3.10 или новее.
При отсутствии рабочего интерпретатора установите
[Python для Windows](https://www.python.org/downloads/windows/)
и заново откройте терминал. Скрипт run.bat проверяет сначала `py -3`,
затем `python` и сообщает об ошибке, если подходящий Python не найден.

На macOS и Linux:

```sh
python3 tools/install_d2.py .cache/d2
export PATH="$PWD/.cache/d2:$PATH"
sh run.sh --config examples/demo.json
```

## Конфигурация

Пример `examples/demo.json`:

```json
{
  "package": "A",
  "source": "repository.json",
  "test_mode": true,
  "version": "1",
  "output": "../output/demo.svg",
  "max_depth": 3
}
```

| Поле | Значение |
| --- | --- |
| `package` | Имя корневого пакета |
| `source` | HTTP(S) URL индекса Packages или путь к тестовому файлу |
| `test_mode` | `true` для тестового файла, `false` для Ubuntu |
| `version` | Точная версия корневого пакета в формате Debian |
| `output` | Имя выходного файла с расширением `.svg` |
| `max_depth` | Целое число от 0; корень имеет глубину 0 |

Все шесть полей обязательны. Пути задаются относительно файла конфигурации.
Выходной каталог создаётся при сохранении. Неверные настройки, отсутствие
пакета или версии, сетевые ошибки и ошибки D2 выводятся в stderr.
Код завершения: 0 при успехе, 1 при ошибке приложения, 2 при неверной
команде запуска. Путь к JSON можно изменить аргументом `--config`.

## Примеры

```sh
make run CONFIG=examples/chain.json
make run CONFIG=examples/cycle.json
make run CONFIG=examples/single.json
make run CONFIG=examples/short-path.json
make run CONFIG=examples/ubuntu-hello.json
make run CONFIG=examples/ubuntu-make.json
make run CONFIG=examples/ubuntu-gzip.json
```

Реальные примеры используют индекс Ubuntu noble/main для amd64 и точные
версии `hello`, `make` и `gzip`. Нужен доступ к интернету.
Для другого выпуска, компонента или архитектуры нужно заменить URL
индекса в `source` и выбрать существующую в нём версию пакета.

Тестовый репозиторий имеет следующий формат:

```json
{
  "packages": {
    "A": {"version": "1", "dependencies": ["B"]},
    "B": {"version": "1", "dependencies": []}
  }
}
```

Имена состоят из заглавных латинских букв. Каждый упомянутый пакет должен
присутствовать в `packages`. Примеры покрывают цепочку, цикл, общий узел,
одиночный пакет и повторное раскрытие по более короткому пути.

## Как строится граф

Поддерживаются несжатые индексы Packages, gzip и xz. Учитываются `Depends`
и `Pre-Depends`, ограничения версий и виртуальные пакеты из `Provides`.
Выбирается первая доступная альтернатива и новейшая подходящая версия
по правилам Debian. Реальный пакет предпочтительнее виртуального провайдера.
Неразрешённая зависимость вызывает ошибку и не скрывается из результата.

DFS реализован явным стеком без рекурсии. Общие и циклические рёбра
сохраняются. Узлы на границе глубины включаются, но не раскрываются;
они помечены `depth limit` на рисунке. Более короткий путь к уже встреченному
узлу позволяет продолжить его раскрытие. Для отрисовки используется D2
с раскладкой ELK. При ошибке рендера прежний SVG сохраняется.

Анализ ограничен одним архитектурным индексом. Квалификаторы `:any`
и `:native` разрешаются внутри него; для явной архитектуры проверяется
совпадение или `all`. Полный multiarch-анализ, состояние установленных
пакетов и глобальное разрешение конфликтов apt не реализованы.

## Основные функции

| Модуль | Назначение |
| --- | --- |
| `config.load_config` | Чтение и проверка шести настроек |
| `versions` | Проверка и сравнение версий Debian |
| `relations` | Разбор зависимостей, альтернатив и Provides |
| `Repository.get` | Поиск заданной версии пакета |
| `Repository.dependencies` | Выбор прямых зависимостей |
| `Repository.from_index` | Чтение готового текста для сравнения |
| `graph.build_graph` | Построение графа нерекурсивным DFS |
| `order.dependency_order` | Порядок зависимостей либо диагностика цикла |
| `visualize.to_d2` | Генерация текста D2 |
| `visualize.render_svg` | Отрисовка и проверка SVG |

## Проверки

```sh
make test
make check
python3 -m pip install -r requirements-dev.txt
ruff check src tests tools
```

Для основных тестов D2 и интернет не нужны. Они проверяют разбор метаданных,
версии, ошибки настроек, глубину, циклы, порядок зависимостей и отрисовку.
Проверка правил контролирует размеры функций, строки, аргументы,
сложность, документацию, структуру и содержимое репозитория.
Ruff дополняет её проверками стиля. Проверки также запускаются в GitHub
Actions для Linux, Windows и macOS. После установки D2 дополнительно
проверяется отрисовка с кириллицей в путях; сравнение с apt выполняется
в Linux.

Без Make, в Windows (cmd):

```bat
set PYTHONPATH=src
py -3 -m unittest discover -s tests -v
py -3 tools/check_rules.py
```

## Этапы разработки

| Ветка | Поведение при запуске |
| --- | --- |
| `stage-1` | Проверка JSON и вывод параметров как ключ=значение |
| `stage-2` | Вывод прямых зависимостей заданной версии |
| `stage-3` | Построение и вывод списка смежности графа |
| `stage-4` | Вывод порядка: зависимости раньше зависимого пакета |
| `stage-5` | Генерация D2 и сохранение SVG |

Каждый этап запускается отдельно из своей версии:

```sh
git switch --detach origin/stage-2
make test
make run CONFIG=examples/demo.json
git switch main
```

На этапе 4 для циклов выводится ошибка: строгого порядка зависимостей
не существует. При ограничении глубины порядок относится только к
раскрытой части графа. Он отличается от сетевого скачивания и практического
плана распаковки и настройки пакетов apt.

Сравнение с apt, команды воспроизведения и объяснения различий находятся
в [docs/comparison.md](docs/comparison.md). Отдельный инструмент сравнения:

```sh
PYTHONPATH=src python3 tools/compare_apt.py --depth 3
```

Ему нужны Linux, `apt-cache` и `apt-get`. Он использует отдельные каталоги
состояния и не устанавливает пакеты. Результаты и SVG создаются в `output/`,
кеш — в `.cache/`. Эти каталоги исключены из Git.
